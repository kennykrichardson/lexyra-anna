# Lexyra for Anna

Lexyra turns rough drafts into polished writing while preserving the author's meaning and voice. This independent Anna App keeps the Lexyra React interface and routes every enhancement through a bundled Python Executa and Anna's host model using reverse Sampling. It does not call Cloudflare, Hugging Face, OpenAI, or another external model provider.

## Writing styles

- Professional
- Articulate
- Concise
- Confident
- Recruiter-Friendly
- Academic

## Project layout

```text
Lexyra-Anna/
├── app.json
├── manifest.json
├── bundle/                         # generated by the frontend production build
├── frontend/                       # React, TypeScript, Vite and original UI assets
├── executas/lexyra-writer/         # Python stdio Executa and protocol tests
├── scripts/build-linux.sh          # Linux x86_64 binary packaging
└── MIGRATION_PLAN.md
```

The original `Lexyra` project is a separate standalone Render application. This project contains no Render API dependency or model-provider credentials.

## Requirements

- Node.js 20+ and npm
- Python 3.10+
- `anna-app` CLI 0.1.61 or newer
- Anna developer account with Sampling permission for real model calls
- Linux x86_64 environment to build and execute the distributable Linux binary

## Build the UI and validate the App

From the project root:

```powershell
cd frontend
npm ci
npm run build
cd ..
anna-app validate --manifest manifest.json --bundle bundle
anna-app validate --manifest manifest.json --bundle bundle --strict
```

## Test the Executa locally

```powershell
python -m venv executas/lexyra-writer/.venv
executas/lexyra-writer/.venv/Scripts/python -m pip install -r executas/lexyra-writer/requirements-dev.txt
executas/lexyra-writer/.venv/Scripts/python -m pytest executas/lexyra-writer/tests
anna-app executa dev --dir executas/lexyra-writer --describe --json
```

Run the App UI harness with a signed-in Anna developer account:

```powershell
anna-app login --host https://anna.partners
anna-app dev --manifest manifest.json --bundle bundle --slug lexyra-anna
```

The local App harness in CLI 0.1.61 does not send the Executa `initialize` handshake, so its reverse-Sampling route cannot verify protocol 2.0 and will correctly be rejected by this plugin. The isolated `anna-app executa dev` runner does negotiate v2, but its one-shot invoke does not populate `params.context.invoke_id`, so it cannot finish a sampling call that meets the platform's attribution contract. Complete real Sampling verification with a platform-installed App/Executa runtime that supports protocol 2.0 and supplies invoke context. Sampling also requires the `llm.sample` capability declaration and the platform's sampling authorization for the Executa. No API key is required by the project.

## Build and smoke-test Linux x86_64 Executa

Run in Linux x86_64 with Python 3.10+:

```bash
cd executas/lexyra-writer
python -m venv .venv
source .venv/bin/activate
python -m pip install pyinstaller
../../scripts/build-linux.sh
```

The build script creates `executas/lexyra-writer/dist/lexyra-writer-linux-x86_64.tar.gz`. It extracts and runs the packaged executable through the Executa describe handshake before reporting success. The artifact is configured in the binary profile of `executa.json`; local development remains the active profile.

On Windows, use an available Linux x86_64 builder (for example, a Linux CI runner) and copy the artifact into the configured destination. Cloud Agent acceptance must be run in Anna's Cloud Agent and must include an actual Sampling-backed enhancement; local checks do not establish Cloud Agent compatibility.

## Fresh-install Cloud Agent acceptance (not yet run)

1. Build and smoke-test `executas/lexyra-writer/dist/lexyra-writer-linux-x86_64.tar.gz` on Linux x86_64 using the commands above.
2. After approval to create a remote App version, run `anna-app apps publish --profile binary` and install that version from the Anna App/Developer UI. The publishing command is deliberately not run by this project workflow.
3. In the App's Executa permissions, grant Sampling. In Cloud Agent, launch the freshly installed Lexyra and submit a short draft with each of the six styles.
4. Verify each response is returned through the Linux Executa and Anna host model and rendered in the UI. Also test empty/oversized input, denied Sampling, model timeout, and recovery after an error.
5. Record the App version, Executa platform shown, model call outcome, each style result, and any errors. Do not mark Cloud Agent acceptance complete based on the local mock tests.
